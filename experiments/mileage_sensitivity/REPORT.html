1. Executive Summary & Core Insights

This report documents a controlled sensitivity experiment conducted on the production XGBoost resale valuation pipeline of DriveWorth. By keeping every vehicle attribute constant and varying only mileage across 26 discrete values from 5.0 to 30.0 km/l, we observe:

  • Strong Non-Monotonicity: The model does not exhibit a continuous or monotonic relationship between mileage and resale price. Predicted price fluctuates across 8 separate local peaks and valleys.
  • Counter-Intuitive Efficiency Valuations: An inefficient car at 10.0 km/l is predicted at ₹6,47,552 (+₹24,825 higher than the 22.54 km/l baseline).
  • Tree Split Invariance: Outputs are mathematically flat at ₹6,47,552 across all inputs from 5.0 to 10.0 km/l because no tree split exists below 10.91 km/l.

C. Confounding and Tree Split Mechanics

The Automotive Confounding Hypothesis
In used car datasets, mileage negatively correlates with selling price overall (r = -0.308) because luxury vehicles (2000–3000cc engines) have low mileage (9–13 km/l) but very high price tags. When testing a hatchback at 12.5 km/l, trees split on low mileage assign positive residual weights meant for larger engine classes. Furthermore, within the 334 Hyundai i20 Diesel samples, 21.19 km/l cars were newer models (mean age 4.57 years, avg price ₹6,81,714) compared to older 21.90/23.00 km/l cars (mean age 8.2 years, avg price ₹4,10,000–₹4,40,000). The model memorized these generational price shifts.

5. Validation and Parity Verification

  • Reproducibility: Tested 7 points across 3 runs. Variance was exactly 0.00% (100% deterministic).
  • Pipeline Parity: API endpoint /api/predict and standalone raw XGBoost calculation produced identical numbers for every case.
  • Input Validation: Negative (-5) and zero (0) mileage yielded 400 Bad Request with message "Please provide a valid positive Mileage." String input yielded 400 Bad Request with message "Mileage must be a valid number."

6. Recommendations for Engineering Team

  1. Train with Monotonicity Constraints: Set monotone_constraints in XGBoost to enforce monotonic behavior where appropriate.
  2. Add Production Range Guardrails: Check vehicle mileage inputs against variant-specific manufacturing ranges and flag extreme out-of-distribution entries.
